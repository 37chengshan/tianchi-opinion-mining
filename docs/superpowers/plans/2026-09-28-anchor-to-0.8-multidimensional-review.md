# 0.7162 Anchor → 0.80 多维度审查报告

## 结论

主路线不需要再次推翻：线上 0.716202 的 `candidate-f9eac4b6d4ea-b384f88e9621` 仍应作为唯一主干；但原执行计划需要做 9 类修正，才能避免再次出现“本地好看、线上失真 / 复现路径被新代码污染 / CV 泄漏 / 资源动态改配置导致不同 fold 不可比”等问题。

## 1. 基线真实性：必须区分四个分数

当前项目中同一 anchor 至少存在四个不同语义的分数：

- Online leaderboard: **0.7162020541** —— 唯一真实线上冠军。
- Legacy full-OOF threshold score: **0.7208976157** —— 历史兼容分数，不应再称“strict OOF”。
- Trusted LOFO threshold score: **0.7173161534** —— 当前最可信离线基准，和线上 0.7162 极接近。
- Optimistic calibration references: `full_oof_after_shrink=0.7266870925`、`in_sample_reference=0.7325927085` —— 仅诊断，不得用于 promotion。

因此以后 Dashboard / report / manifest 必须固定显示：`online_f1`、`trusted_lofo_f1`、`legacy_compat_f1` 三列；任何单一“champion_f1”字段都容易误导。

## 2. Anchor 复现：当前 neural.py 已被后续实验污染

当前 `src/opinion_mining/neural.py` 已经包含：

- official offset mapping；
- `OpinionTerm="_"` sentinel；
- multi-hot 39-class relation target；
- pointer beam/NMS；
- 新 relation head；
- 后续 ResourceGuard 逻辑。

历史 0.7162 checkpoint 不能直接用“当前类 + strict=False”加载，否则新增 head 可能随机初始化却参与推理。正确做法是：

1. 先用历史 `fold_*/test_candidates.json` 合并，验证 artifact-level `Result.csv` 精确复现 SHA256；
2. 检查 checkpoint state_dict key schema；
3. 单独实现 `LegacyAnchorPointerModelV0` / legacy feature builder / legacy decoder；
4. checkpoint 必须 `strict=True` 加载；
5. 旧路径和新 challenger 物理隔离，不在同一个 Dataset/Model 类里靠大量 flags 模拟。

Artifact-level SHA 复现是硬 gate；checkpoint-level score parity 是第二 gate。若受 Transformers 版本影响无法逐浮点一致，可接受 candidate key 完全一致 + score tolerance，并记录环境差异，但不得静默 fallback。

## 3. 验证协议：0.7209 存在模型选择 / 阈值同 fold 乐观偏差

历史 `NeuralTrainer` 会：

- 每个 fold 根据该 fold validation monitor F1 选 best epoch；
- 聚合全部 OOF 后再用同一 OOF 选 threshold。

所以 0.7208976 是兼容性参考，不是严格未来泛化估计。

新实验必须：

- 固定 epoch count；held-out fold 不参与 checkpoint 选择；
- threshold 使用 LOFO / cross-fit；
- full-OOF-fit threshold 只用于最终 test inference，不能作为 reported trusted score；
- 所有 ablation 报告 paired fold delta；
- 增加 review-id paired bootstrap（建议 2000 次）评估 F1 delta 稳定性，避免追逐 0.001~0.003 噪声。

Promotion 建议要求：总 delta 达到该阶段门槛，且 bootstrap 90% 区间不明显跨负值，或至少 4/5 fold 不劣于 parent。

## 4. Fold 设计：保持历史可比性，但加分布审计

目前使用普通 shuffled KFold。不要为了“更漂亮”重新生成 stratified folds，否则失去与 0.7162 anchor 的直接可比性。

但必须新增 fold distribution audit：

- gold quadruple count；
- explicit / implicit-A / implicit-O / dual；
- 13 Category；
- 3 Polarity；
- 1/2/3+ quadruples-per-review。

若 rare class 极端偏斜，只做诊断，不改历史 folds。模型 promotion 仍以 pooled micro-F1 为主。

## 5. 错误预算：0.8 不可能只靠三个 correctness fix

Anchor error profile：

- TP=4626, FP=1576, FN=2006；
- FN implicit Aspect=1218；
- FP span/unseen-opinion=1136；
- FP wrong category/polarity=259；
- FP wrong pair=181；
- 训练 gold 中 implicit-A=4735/6633，implicit-O=172/6633。

因此 priority 应为：

1. **implicit-A recall**；
2. **opinion/span boundary precision**；
3. pair relation；
4. category/polarity。

粗略 headroom：仅 +100 TP 大约只能带来约 +0.01 F1；仅移除 300 FP 约 +0.017；要从 0.72 走到 0.80，需要“数百 TP 回收 + 数百 FP 消除”的组合，不能期待 offsets/implicit-O/multi-relation 三个修复单独完成目标。

因此 B1/B2/B3 仍要做，但它们属于 correctness floor，不是 0.8 的主要增益来源。

## 6. 模型路线：不要重新实现一套 OpinioNet

当前 Anchor 本身已经是 one-stage pointer/objectness 家族。原计划“重新实现 OpinioNet-style module”存在重复造轮子和引入回归的风险。

应改成：

- 先冻结 legacy head；
- 在完全相同 head 下测试 WWM/RoBERTa/MacBERT，真正隔离 backbone 效应；
- 然后只对 top-2 做 error-driven head ablation：
  1. joint 39-class relation（仅当 legacy 是 separate C/P）；
  2. separate implicit-A / implicit-O state head 或独立 virtual sentinel；
  3. boundary hard-negative / near-span ranking（±1 token、superset/subset、邻近词）；
  4. objectness hard-example margin loss。

每次只改一个主变量。

近期 ASQP 研究支持对 explicit/implicit 做独立提示或 special token；但旧 Grid 已证实“复杂结构本身”不等于更好，所以不恢复 dense Grid 主线。

## 7. TAPT / 数据增强：必须 fold-safe，优先级下降

当前 `run_mlm_adaptation.py` 如果用全部 3229 train reviews 先适配，再做 OOF，会让 held-out fold 文本参与 MLM adaptation。虽然无标签，但会让严格 OOF 偏乐观。

修正：

- OOF 阶段：每个 fold 的 TAPT corpus 只能来自该 fold train rows；
- final test：配置冻结后，才允许用全部 train reviews 训练 adapted backbone；
- 不使用 test text 做 TAPT；
- 外部电商语料、test pseudo-label、外部在线 LLM 数据增强全部先进入 `compliance_blocked`，直到当前赛题官方规则明确允许。

论坛提到 punctuation split / LLM rewrite augmentation，但同源 OpinioNet 也记录过 augmentation 略降，因此只保留一个官方数据内、可逆的 punctuation split ablation：仅切分“所有 gold span 完整落在同一 segment”的样本，offset 重新平移，augmentation 只在 train fold 内生成。

## 8. ResourceGuard：禁止不同 fold 用不同有效配置

当前 neural trainer 可能在训练中动态改变 `trainable_layers/max_length`，而 optimizer 已创建。即使没有报错，也会导致实验语义不稳定。

新 Anchor runner 必须：

- 训练前 preflight 决定一个 experiment-wide effective config；
- 每 20 step 只监控，不直接修改 optimizer 参数集合；
- RED memory pressure → 保存诊断、终止当前 experiment；
- 选择统一 safe profile 后从 fold1 重新跑全部 folds；
- 不允许 fold1 用 4 层、fold2 用 2 层这种 mixed-config OOF；
- Dashboard 同时展示 requested_config / effective_config / restart_reason。

## 9. Ensemble：先验证候选互补，再做低维校准

之前 group calibration 出现明显过拟合，因此禁止再做 category/state 高维 threshold 搜索。

建议流程：

1. 每个模型先在自己的 5 folds 内平均 raw candidate score；
2. 计算 best-single candidate oracle、union oracle、unique TP / unique FP；
3. union oracle 相对 best single 至少 +0.015 才值得 ensemble；
4. score scale 只用低维校准（global Platt / temperature，必要时仅 explicit-vs-implicit 两组）；
5. 校准参数必须 fold-exclusive；
6. 模型间只搜索少量离散权重；
7. 最终 threshold 同样分 trusted LOFO 和 full-OOF test threshold 两种用途。

## 10. Qwen：提早做低成本 complementarity pilot，但延后重训练

论坛的 `Qwen3-8B Score 0.81` 是社区作者自报，页面没有足够细节，不可当作可复现保证。但它证明 LLM 路线值得保留。

本机策略：

- 先 Qwen3-4B 4-bit MLX inference/RAG verifier；
- prompt 只输出严格 JSON，不输出 CoT；近期 ASQP LLM 研究也显示 few-shot demonstration 本身可优于 CoT；
- BM25 Top20 → rerank Top5；
- pilot 只验证 parse rate、exact-substring validity、anchor unique-FN recovery precision，不作为 promotion score；
- 只有 pilot 显示明显 complementarity，才做 QLoRA；
- 完整 promotion 仍必须 full-fold cross-fit；
- Qwen 不可单独删除高置信 Anchor candidate，优先做 missing-quad proposer / disagreement resolver。

## 11. 线上提交纪律

- 0.716202 始终是 immutable online champion，直到新的 LB 真正超过它；
- 每个 candidate 必须记录 parent、单一 hypothesis、source hash、trusted LOFO、legacy compat、online score；
- 只有 trusted delta >= +0.005（或 ensemble +0.004 且互补证据明确）的候选进入常规上传；
- diagnostic submission 最多一次验证一个清晰分布假设；
- 若连续两个控制良好的候选 local ranking 与 LB 反向且差距 >0.02，暂停该 family，先审查 split shift / calibration。

## 12. 工程复现

每个 promoted run 必须保存：

- config.json；
- source_manifest.json（关键源码 SHA256）；
- env_manifest.json（Python/PyTorch/Transformers/tokenizer/model revision）；
- fold_assignments.json；
- oof_candidates.json；
- fold raw test candidates；
- trusted_report.json；
- compatibility_report.json；
- error_buckets.json；
- resource_report.json；
- Result.csv + SHA256（只有 upload-eligible candidate）。

由于当前项目 Git 状态不适合作为唯一复现依据，源码 hash 是硬要求。

## 最终调整后的优先级

`Anchor artifact/schema freeze → trusted evaluator/statistical gate → B1/B2/B3 correctness → same-head strong encoder → implicit/boundary targeted ablations → official-only augmentation/TAPT if proven → EMA/FGM → 5fold finalists → complementarity-aware ensemble → Qwen/RAG verifier → optional compliant pseudo-label → online`。

0.80 是 stretch target，不承诺；但这个顺序最大化“每一步可归因、可回退、不会把线上已验证的 0.7162 丢掉”。
