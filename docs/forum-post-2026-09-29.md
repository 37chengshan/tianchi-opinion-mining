# 从 0.7162 到 0.7734：评论观点挖掘 ACOS 四元组方案（含失败清单与复现入口）

> **代码与复现入口**：https://github.com/37chengshan/tianchi-opinion-mining
> **线上成绩**：strict 四元组 F1 **0.7734**（天池评测系统 8 次真实提交，最高一次见下表）
> **训练环境**：Apple M1 Pro / 16GB 统一内存（本地训练，无云端 GPU）
> **可验证性**：`python3 -m pytest -q` → `123 passed, 3 skipped`；全部线上提交文件与 SHA256 已归档

## 一、结果先行

| --- | --- | ---: | ---: |
| 0 | 历史基线：`hfl/rbt3` 单阶段 span/relation，5 折 | 0.7209 | 0.7162 |
| 1 | 换 backbone：`hfl/chinese-roberta-wwm-ext` 5 折 × 4 轮 | 0.7543 | 0.7583 |
| 2 | + 长训练成员：WWM 5 折 + WWM 3 折 × 8 轮（1 : 0.7） | 0.7693 | 0.7645 |
| 3 | 单模型试投：WWM 5 折 × 10 轮 / WWM 3 折 × 8 轮 | 0.7731 / 0.7637 | 0.7633 / 0.7559 |
| 4 | + 多样性成员：三源（1 : 0.7 : 0.3） | 0.7682 | 0.7668 |

两个必须先说清楚的观察，它们决定了后面所有决策：

1. **线上分系统性地低于本地无泄漏分**（−0.0014 ~ −0.0048）。所以本地分只能当筛选门禁，**任何替换都以线上实测为准**，本地高 0.001 不算高。
2. **上限不在模型，在决策层**。WWM 候选集合的**金标覆盖已达 0.9772**，也就是说金标里有 97.7% 的答案模型其实生成出来了；完美排序的理论上限是 F1 0.9885。而阈值决策实际只做到 0.754。把力气花在"更好的重排序"上，不如花在"更多样、更强的成员 + 折安全的融合"上。

## 二、赛题与评测口径

从中文电商评论里同时抽出 **(Aspect, Opinion, Category, Polarity)** 四元组：方面词、观点词、类别、极性。评分是**严格四元组 micro-F1** —— 四个字段全部命中才算一条正确，错一个字段等于零分。这带来两个直接后果：

- **不能靠堆召回拿分**：多输出 1 条错的就是 FP，P 与 R 必须同时成立；
- **解码约束比模型容量更早成为瓶颈**：start/end 位置、`_`（隐式观点）哨兵、类别的 39 类联合空间，任何一处不一致都会整条作废。

数据规模：训练 **3229 条评论 / 6632 条金标四元组**，测试 **2237 条评论**；单条评论最长只有 **72 token** —— 这条事实后来直接否掉了一个实验方向（见第五节）。

## 三、方案：单阶段 span/relation 抽取 + 折安全决策层

![训练与推理流水线](https://raw.githubusercontent.com/37chengshan/tianchi-opinion-mining/main/assets/readme/workflow.svg)

**模型侧（单阶段，不用 dense 网格）**

| 项 | 取值 |
| --- | --- |
| 主干 | `hfl/chinese-roberta-wwm-ext`（对比 `hfl/rbt3`、`hfl/chinese-macbert-base`） |
| 序列 | `max_length=96`，`batch=4`，梯度累积 2 |
| 优化 | lr `2e-5`（长训练档 `1.2e-5`），head lr `8e-4`，weight decay `0.01` |
| 可训练层 | 后 2 层 + head |
| 轮数 | 4 / 8 / 10（长训练是后来发现的增益来源） |
| Head | 客观性打分 + 4 个指针（方面/观点的起止位置）+ 类别×极性联合分类（39 类） |
| 解码 | 起点不晚于终点、跨度 ≤ 10、隐式观点用 `_` 占位、重叠候选去重、每个方面最多保留 2 条关系 |

**决策侧（本方案最关键的部分）**

- **折安全（fold-safe）**：阈值与融合权重只在**其他折**上拟合，被评分的那一折只做应用。凡是在评估折本身上调参得到的分数，一律不算数、不用于决定晋级 —— 这是"本地 0.78、一上线就掉"最常见的原因。
- **单变量门禁**：每次实验只改一个配置项，只有当无泄漏分数提升达到 0.004 以上才保留；不达标就回滚，绝不叠加两个尚未验证的技巧。
- **成员按异构选，不按最强选**：四源里包含 8 轮/10 轮两个训练长度、3 折/5 折两种划分、WWM/MacBERT 两个主干。第 4 次提交（三源，本地 0.7682）本地比二源低 0.0011，线上却高 0.0023 —— 这条证据直接改变了后面的选人标准。
- **概率级融合**：候选先归一化再按源加权（最终 1 : 0.7 : 0.4 : 0.3），而不是在答案集合层面做规则合并。

## 四、单项消融（3 折、固定划分、同参、单变量）

历史 RBT3 基线（同折同参）：**0.6874**

| 实验（每次只开一个修正） | 严格 F1 | 提升 | 是否保留（要求 ≥0.004） |
| --- | ---: | ---: | --- |
| 官方偏移量解码（偏移取自 tokenizer 官方映射） | **0.7140** | +0.0266 | 通过 |
| 隐式观点哨兵（无观点词时用 `_` 占位而不是丢弃） | 0.7116 | +0.0241 | 通过（这一类的召回 **0.0000 → 0.3547**） |
| 多关系保留（同一方面允许多条观点共存） | 0.7064 | +0.0189 | 通过 |
| 三项同时开启 | 0.7140 | +0.0266 | 与"官方偏移量解码"单独开启**完全相同**，没有叠加增益 |

结论很反直觉但很重要：三项修正单独都过门禁，**合在一起却等于第一项单独**。增益集中在"偏移量与解码一致性"上；隐式观点哨兵的价值在于把这一类样本的召回从 0 拉起来，避免整类样本被直接丢弃。

## 五、失败清单（同样重要，避免后来者重复踩）

| 路线 | 实测 | 处理 |
| --- | --- | --- |
| 稠密网格方案（Grid V2，逐格打分）+ 成对过滤融合 | 无泄漏交叉拟合 **0.6337** | 整条路线淘汰，单阶段 span/relation 才是主线 |
| 论文式结构增强（OpinioNet-style，RBT3 控制组） | 0.7088 vs 0.7140 | 未过 −0.002 门禁 |
| 本地 QLoRA（通义千问 Qwen3-4B，4-bit 量化） | 第 1 折 **0.6417**（P 0.6688 / R 0.6167） | 量化 + 短训不足，降级为校验器/挑战者 |
| 重排路线（BM25 / 先验分数重排） | 0.7180 ~ 0.7527 | 未超过同参数单阶段模型 |
| 加大 `max_length` | 最长评论 72 token，96 已无截断损失 | 不是瓶颈，放弃 |

**关于 LLM 直抽这条路**：我们用通义千问 Qwen3-4B 在本赛题数据上做了真实的 QLoRA 微调实验（4-bit 量化权重、批大小 1 + 梯度累积、短上下文，2 轮 / 2152 步；输出严格 JSON、无观点词时用 `_` 占位，**解析失败 0 条**），第 1 折严格 F1 = **0.6417**（1077 条验证，2023 条预测，2194 条金标），对照同折 BERT 是 0.7442。差距不在"LLM 不行"，而在**本地的量化 + 短训条件**：4-bit 权重 + 单卡统一内存，训练轮数与序列预算都被压住。同赛题的公开方案用云端 bf16 LoRA，同一份数据可以到 Qwen3-4B 0.75 / Qwen2.5-7B 0.78 / 32B 0.81 档 —— 所以这条路线被保留为"云端再战"，而不是在本地硬堆。

## 六、阿里云产品使用说明

本项目从平台、模型获取到模型微调实验都在阿里云生态内完成：

**1）天池平台（评测与提交）**
全部线上分数来自天池评测系统的真实提交：共 **8 次评测**（历史基线 0.7162，本轮 7 次：0.7559 / 0.7583 / 0.7633 / 0.7645 / 0.7668 / 0.7702 / **0.7734**）。每次提交的文件、行数、预测四元组数与校验值都归档在仓库的提交目录中，可逐条复核。

**2）魔搭 ModelScope（模型获取，阿里云）**
仓库提供一条命令取主干权重：自动把 Hugging Face 上的模型名解析到魔搭上的对应仓库（国内直连，无需代理），下载完成后校验配置文件、分词器与权重文件是否齐全，并输出一份可贴进实验记录的摘要：

```bash
python3 scripts/fetch_model.py --model hfl/chinese-roberta-wwm-ext --out models/wwm
# 默认走魔搭（ModelScope）；需要时可用 --source hf 切回 Hugging Face
```

**3）通义千问 Qwen3-4B（阿里云开源模型）微调实验**
如第五节所述，我们在本赛题数据上真实跑过 **Qwen3-4B 的 QLoRA 微调**（4-bit 量化权重、LoRA 适配器、批大小 1 + 梯度累积、短上下文），并用与 BERT 主线**完全相同的严格评分器**打了第 1 折：**0.6417**，且 0 条解析失败（说明提示词模板、JSON 输出约束与子串校验这条工程链路是通的）。这个负数结论直接决定了 Qwen 在本方案中的角色：**只做长尾/隐式样本的校验器与挑战者，不做主模型，也不允许直接覆盖高置信的 BERT 集成输出**。

**4）PAI-DSW 云端复现路径（云端路线规划，非本机实跑）**
本仓库训练脚本为纯 PyTorch，可直接在 PAI-DSW Notebook 中以相同命令、相同 fold 划分运行；同时仓库已提供云端训练配方（bf16 LoRA：学习率 1e-4 + cosine 预热、秩 16/alpha 32、截断 1024、批大小 4 × 梯度累积 8、3 轮）与打包脚本（把数据、提示词模板、评分脚本、训练配置打成一个不含任何密钥的压缩包）。评测口径与本地一致，云端回传预测文件后即可用同一评分器对齐比较。

## 七、复现步骤

```bash
git clone https://github.com/37chengshan/tianchi-opinion-mining.git
cd tianchi-opinion-mining
export PYTHONPATH=src

# 1) 环境自检（不需要赛题数据、不需要 GPU）
python3 -m pytest -q                 # 123 passed, 3 skipped

# 2) 取主干权重（默认走魔搭 ModelScope）
python3 scripts/fetch_model.py --model hfl/chinese-roberta-wwm-ext --out models/wwm

# 3) 放入赛题数据（Train_reviews.csv / Train_labels.csv / Test_reviews.csv）
#    数据目录结构见仓库内说明；数据未随仓库分发

# 4) 训练 + 严格评估（这里以 5 折、每折 4 轮为例）
python3 scripts/run_anchor.py \
  --train-reviews artifacts/data/train/TRAIN/Train_reviews.csv \
  --train-labels  artifacts/data/train/TRAIN/Train_labels.csv \
  --test-reviews  artifacts/data/test/TEST/Test_reviews.csv \
  --fold-assignments artifacts/reports/fold_assignments_seed42.json \
  --model-name hfl/chinese-roberta-wwm-ext \
  --n-splits 5 --epochs 4 --name wwm_5fold

# 5) 折叠安全融合并生成提交（阈值只在其他折拟合）
python3 scripts/ensemble_submit.py --run artifacts/experiments/wwm_5fold --name wwm_5fold_ensemble --n-splits 5
```

**硬件与时间参考**：M1 Pro 16GB，全部本地训练。RBT3 3 折筛选约 14 分钟（每折 290 秒）；WWM 单折约 29 分钟（5 折 × 4 轮）；MacBERT 单折约 14 分钟。所有实验都是本地单机可复现规模。
